# 看图识谱 → MusicXML

核心思路：**不依赖 OMR 软件**，因为截图和低分辨率图上错误太多，修起来比重读还慢。脚本负责测量，模型逐小节看图读谱，写成紧凑的文本转写，再编译成 MusicXML。

## 适用范围

- **能处理：** 印刷或软件排版的五线谱，包括截图、扫描件，以及轻微倾斜、底色不均的照片。线距（相邻两条谱线的间距）不小于 5px 即可，不小于 10px 时最稳。每行谱表的数量要一致，比如钢琴每行 2 个、旋律每行 1 个。
- **处理不了：** 手写谱；透视变形明显的照片（先让用户裁正，或重拍）；同一次运行里不同行谱表数量不一样的总谱（把页面分成几次运行，或只转用户要的声部）。

## 环境

`measures.py` 和 `ascii.py` 依赖 Pillow，装在临时 venv 里（装包需要网络权限）：

```bash
python3 -m venv /tmp/omrvenv && /tmp/omrvenv/bin/pip -q install pillow
```

`build_musicxml.py` 只用标准库。下文 `S=.agents/skills/score-image-to-musicxml`。

## 流程

```
- [ ] 1. 看整页：确定每行谱表数、谱号、调号、拍号、结构记号
- [ ] 2. measures.py 切小节，用总览图核对小节线，必要时修正后重跑
- [ ] 3. 逐小节读谱（放大图 + heads.txt，存疑处用 ascii.py）
- [ ] 4. 写转写文件，用 build_musicxml.py 编译，修到时值校验通过
- [ ] 5. 复查重点小节，告诉用户存疑处，清理临时文件
```

### 1. 看整页

用 Read 看原图，确定：

- 每行几个谱表、从上到下各是什么谱号，作为 `--staves-per-system` 和 `--clefs` 的参数；
- 调号（`fifths`，降号写负数）、拍号、速度；
- 反复记号、1./2. 房子、8va/8vb 的范围、力度和渐强渐弱、中途换调号/拍号/谱号的位置；
- 有没有弱起小节，有没有歌词。

### 2. 切小节并核对

```bash
/tmp/omrvenv/bin/python $S/scripts/measures.py p1.png p2.png ... -o /tmp/score-work --staves-per-system 2 --clefs G,F
```

- 图片按页序传入。谱号可以写 `G`、`F`、`C`（中音谱号），或 `G8`（下加八度的高音谱号，常见于男声声部）。
- 输出：
  - `overview/pN.png`：整页总览，红框是检测到的小节线，蓝字是小节号；
  - `crops/mNN.png`：每小节放大图，左侧标音名，红色表示五线；
  - `heads.txt`：符头的 x 坐标和音高猜测，`o` 后缀表示空心符头；
  - `pages/` 和 `layout.json`：给 `ascii.py` 用的页面和版面信息。
- **先看每页的 overview，并把总小节数和谱面核对，再开始读谱。** 小节线可能多检，常见于长符干、贯穿整个谱表的连线；也可能漏检，常见于小节线和音符、连线挨得太近。修正后重跑：
  - `--drop-bar 页:行:x`：删掉 x 附近误检的线。x 取 heads.txt 中这一小节标题里的边界值。
  - `--add-bar 页:行:x`：补一条漏检的线。x 用 `ascii.py` 看那一小节，找出整列贯穿五线的位置，坐标读顶部的刻度。
  - 两个参数都可以重复使用。“行”是这一页从上往下数的第几行谱。
- 没有开头小节线的单谱表，第一小节会包含谱号和拍号区域，属正常情况。

### 3. 逐小节读谱

每小节 Read 一次 `crops/mNN.png`，同时参考 `heads.txt` 对应的那一行：

- **heads.txt 只是线索。**
  - 谱号、调号、拍号、升降号、附点、歌词、小节号都可能被误检成符头。
  - 和弦里挨得很近的音、加线上的音可能漏检，或者差一级。
  - 休止符、附点、延音线、连梁层数都要看图判断。
- **时值看符头和连梁。**
  - 空心符头没有符干是全音符，有符干是二分音符。
  - 一根梁是八分，两根是十六分；只在局部出现的短梁或单侧小钩，表示那一个音是十六分。
  - 附点在符头右侧。连音符上方有数字 3。
- **用 ASCII 视图精读。** 凡是和弦、加线音、空心音，或者检测结果和旋律走向对不上的地方，都用它确认：

```bash
/tmp/omrvenv/bin/python $S/scripts/ascii.py /tmp/score-work/layout.json 13 --staff 1 [--x0 515 --x1 585] [--above 4 --below 4]
```

  - 左侧 `F5-` 表示这一行是线，`E5 ` 表示间的中心。
  - 取符头 `#` 所占行的中点：落在 `X-` 行就是线上的音，落在 `X ` 行就是间里的音。
  - 高分辨率图会自动缩采样，顶部刻度标的是原图的 x 坐标。
- **调号与临时记号。**
  - 调号内的音直接写音名，不写升降，编译器会自动套用调号。
  - 临时升降写 `#`/`b`，还原写 `n`。小节内后面同音高的音，编译器会沿用前面的临时记号。
- **重复的段落也要逐个小节看。** 看起来一样的小节，常在伴奏音型、八度或尾音上有差别。
- **多声部。** 同一谱表上有两组符干方向相反、节奏不同的音时，用 `&` 分成两个声部。节奏相同的话，直接写成和弦更简单。

### 4. 转写文件

完整示例见 [examples/syntax.txt](examples/syntax.txt)。

```text
title: 曲名
composer: 作曲
lyricist: 作词        // 可选
fifths: -2            // 调号，降号为负
time: 4/4
clefs: G F            // 每个谱表一个；单行旋律只写 G
tempo: 72             // 可选
let GM = G3+D4+F4:2 E3+B3+D4:2   // 宏，用 $GM 引用

1 | A4:8 B4:16 B4:16~ B4:8 G5:8 F5:4 B4:8 D5:8 | $GM | p
2 | C5:4 D5:8/3 E5:8/3 F5:8/3 G5:2 & E5:2 C5:2 | F2:1 | system
```

每行格式为 `小节号 | 谱表1 | 谱表2 | 记号`，最后的记号栏可以省略。`#` 开头的行和 `//` 后面的内容是注释。

**音符写法：**

| 写法 | 含义 |
|---|---|
| `C5:8` | 音名+八度:时值，时值可取 `1 1. 2 2. 4 4. 4.. 8 8. 8.. 16 16. 32` |
| `G3+D4+F4:2` | 和弦 |
| `r:4` | 休止符 |
| `Ab4` `F#4` `Gn5` | 临时降、升、还原记号 |
| `E5:8/3` | 三连音（`/6` 是六连音），编译器自动加括号并校验时值 |
| 后缀 `~` | 延音线连到下一个同音高的音（可以跨小节） |
| 前缀 `(` 和后缀 `)` | 圆滑线的开始和结束 |
| 后缀 `!` | 延长记号 |
| 后缀 `=` | 强制和下一个音连梁（跨拍连梁，比如 3+3+2 分组） |
| 后缀 `"字"` | 歌词。以 `-` 结尾表示同一单词还没完，例如 `"Hel-"` `"lo"`；歌词里的空格写成 `_` |
| 前缀 `g` | 倚音：`gF4:8` 是带斜线的八分倚音，`gG#4:16` 是十六分倚音 |
| `A & B` | 同一谱表上的两个声部，每个声部单独满足时值 |

**记号栏**（多个记号用空格分隔）：

- **力度：** `p` `mp` `mf` `f` `ff` 等，以及 `cresc` `dim`。加 `@n` 表示从第 n 个十六分音符处开始，例如 `p@8`。
- **渐强渐弱楔形：** `<` 开始渐强，`>` 开始渐弱，`wedge-stop` 结束。
- **八度记号：** `8va`、`15ma`、`8vb` 从本小节开始，`8va-end` 等在本小节结束。**谱表 1 里写印刷上的音高**，编译器会移八度，并输出 `<octave-shift>`。本项目读的是 `<pitch>`，所以生成的 XML 里是实际发音音高。
- **反复与房子：** `repeat-start`、`repeat-end`；`ending1-start`、`ending1-stop`、`ending2-start`、`ending2-open`（最后一个房子右侧不封口）。
- **中途变化：** `key=-3` 换调号，`time=3/4` 换拍号，`clef2=G` 换谱号（数字是谱表序号），都从本小节开始生效。
- **其他：** `system`（本小节换行）、`page`（本小节换页）、`double`（双小节线）、`final`（终止线；最后一小节自动加）、`pickup`（弱起小节，不做时值校验）、`text=rit.`（文字，空格写成 `_`）。

编译：

```bash
python3 $S/scripts/build_musicxml.py /tmp/score-work/score.txt -o "src/assets/<合集>/<曲名>.musicxml"
```

- 每个谱表的每个声部，时值都必须等于拍号；不等时会报出小节号和实际拍数。这时回到图上，找漏掉的附点、休止符、连音或连梁层数。
- 编译器会按拍自动连梁（6/8 等复拍子按附点四分分组），延音线未闭合会给出警告，有 xmllint 时还会自动做 XML 校验。
- 曲库位置是 `src/assets/<合集>/`，由 `scoreCatalog.js` 自动收录。用户没指定合集时，先问用户。

### 5. 收尾

- 抽查最容易错的地方：加线上的音和低音八度、和弦内部、终止和弦、倚音与连音、8va 段落、换调后的升降。
- 回复用户时，**列出存疑的小节和可能的另一种读法**，不要只报“完成”。
- 删除 `/tmp/score-work` 和 `/tmp/omrvenv`。

## 不支持

同一谱表超过 4 个声部、五连音和七连音、装饰音记号（颤音、波音等）、踏板、多乐器分谱（part）。遇到这些时，告诉用户简化了什么。
